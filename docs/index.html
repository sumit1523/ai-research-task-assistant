What users can do

Enter a question, then optionally add trusted notes, public webpages, or PDF/text/Markdown files. The app returns a research summary, a critic review, a timed action plan, and persistent progress checkboxes. A user can then ask for a realistic revision such as “I only have 30 minutes a day.”

1

The streamlined input area accepts one goal plus optional notes, URLs, and files. Sources are labelled before they enter the workflow.

2

Review the AI team’s work

Tabs separate the final answer, the Researcher and Critic handoff, and the plan’s progress/source view.

3

Act and adapt

Numbered tasks become persistent checkboxes. Feedback triggers the Planner to generate a replacement plan.

All AI agents used

This is a genuine role-based multi-agent workflow. All three agent roles use the hosted Qwen model, but each has a separate prompt, responsibility, input, output, and handoff. The LangGraph Coordinator is deterministic workflow logic rather than a fourth LLM agent.

🔎 Researcher Agent

Goal: turn prepared context into an evidence-aware research brief.

Input: question and split source excerpts.

Output: 3-6 key findings plus assumptions or information gaps. It is instructed to preserve [Source: ...] labels and never create the final task plan.

🛡️ Critic Agent

Goal: audit the Researcher’s brief before anyone plans from it.

Input: question and research brief.

Output: APPROVED or NEEDS_REVIEW, plus strengths, risks, unsupported claims, or missing information. It does not make the plan.

🗓️ Planner Agent

Goal: create practical next steps from reviewed research.

Input: question, research brief, critic decision, and critique.

Output: a 3-5 bullet summary and 4-7 numbered tasks with time estimates. It also owns the user-feedback revision path.

How the agents collaborate

Normal research path

START → decide → prepare_context → researcher → critic → planner → END

The Planner receives the critic’s decision even when it is approved. If the Critic identifies uncertainty, the Planner must be cautious or include a research task instead of inventing a fact.

Clarification and revision paths

A question with fewer than four words routes to clarify, which asks for a goal, time, level, or desired result. Existing plan feedback routes directly to revise, where the Planner receives the prior summary, plan, and user constraint.

Where LangChain is used

Source preparation

RecursiveCharacterTextSplitter creates 700-character chunks with 100-character overlap. This is a lightweight RAG-style context step. The current MVP uses the first six chunks; true vector retrieval is a planned improvement.

Prompts and model calls

Each role uses its own ChatPromptTemplate. ChatGroq calls the cloud-hosted qwen/qwen3.6-27b model. Temperature is 0.2, output is capped at 700 tokens, and internal reasoning is disabled/hidden for clean user-facing output.

Source ingestion and grounding

Web pages

Public HTTP(S) URLs are fetched with a timeout. Local URLs are rejected. Navigation, scripts, headers, footers, and styles are stripped so the workflow receives readable page text rather than website chrome.

Files

PDF, TXT, and Markdown uploads are read in memory and capped at 20,000 characters. PDF extraction uses pypdf[crypto]; protected files receive a friendly upload-an-unlocked-copy message.

Labelling

Every input is wrapped as [Source: name]. The Researcher is prompted to retain these labels for factual claims, making the research brief easier to audit.

Grounding guardrail

With no source text, the Researcher must identify findings as general guidance. This reduces overconfidence but is not a replacement for human verification.

Modern Streamlit user experience

Guided first screen

A visual team introduction and one bordered input workspace replace a long technical form. Optional evidence inputs are clearly separated from the required question.

Visible collaboration

A status panel explains the Researcher, Critic, and Planner handoff. The collaboration tab exposes the actual research brief and critic review rather than hiding them behind one answer.

Focused workspace

Tabs separate final output, agent handoff details, and progress. The sidebar gives a compact team guide, LangSmith status, and the five most recent locally saved projects.

Data, privacy, and safety

SQLite persistence

research_tasks.db is local. The sessions table stores question, summary, task-plan text, and timestamp. The task_items table stores individual task text, completion status, and its session relationship.

Secrets

.env stores keys locally and is excluded by .gitignore. The public GitHub repository and Pages site never include the database, virtual environment, or secrets.

User control

The app does not email, purchase, post, or change external accounts. It recommends, plans, and revises only after the user chooses to run a session or request a revision.

Clear errors

Source-loading errors and cloud-model errors are handled separately. Users receive actionable file, URL, encryption, or provider information instead of a generic failure.

LangSmith observability and evaluation

Tracing: with a valid LANGSMITH_API_KEY, LANGSMITH_TRACING=true, and LANGSMITH_PROJECT, LangSmith records the complete nested execution: Coordinator route, each agent call, prompts, model output, latency, and errors.

Offline evaluation: evaluation_examples.json contains stable example questions. evaluate.py runs them through the graph and checks for a summary, task plan, and an expected concept. With tracing configured, those evaluation runs appear in the same LangSmith project.

Important: LangSmith is optional for the app to function. It requires a valid user-owned key; no tracing project exists until the first traced run succeeds.

Configuration, deployment, and project map

Required configuration

GROQ_API_KEY enables hosted Qwen calls. GROQ_MODEL can override the default model. No local LLM download is required, but Groq free-tier rate and token limits apply.

GitHub Pages

This guide is plain static HTML in docs/. GitHub Pages publishes that folder from the main branch, so documentation changes are versioned and deployed with the code.

Key files

app.py is the UI; assistant_graph.py is the multi-agent graph; source_loader.py handles input; storage.py owns SQLite; evaluate.py runs checks.

Known limits and next steps

Current retrieval uses first-chunk context, citations are labels rather than claim-level links, and critic feedback does not yet trigger an automatic re-research loop. Next steps are embeddings/vector retrieval, source citations, richer task metadata, and a Critic-to-Researcher retry branch.
