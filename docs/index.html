What the app does

Instead of being a generic chat box, the assistant follows a visible, stateful workflow and keeps useful work local.

1

Bring trusted context

Paste notes, add public webpage URLs, or upload a PDF, text, or Markdown file.

2

Get a grounded answer

The assistant prepares source text, produces a concise summary, and labels the inputs it used.

3

Take action

Receive timed tasks, check them off, see progress, and ask the agent to revise the plan.

Detailed request lifecycle

1. Validate the input

The interface requires a research question. It accepts optional pasted notes, public web URLs, and multiple uploaded files. Empty questions are stopped before any model call.

2. Ingest and label sources

Each source becomes a pair of name and text. The app combines them as [Source: name] blocks so the model can identify where its context came from.

3. Build graph state

The initial state contains the question and combined source text. A revision run instead carries the original question, previous summary, previous task plan, and the user’s requested change.

4. Route the agent

The graph begins at START and always runs decide. It then follows one conditional edge: clarification, research, or revision. Each path ends cleanly at END.

5. Generate structured sections

The model is asked to return a SUMMARY followed by a TASK PLAN. The app separates those headings into the two columns users see.

6. Save and track action

The result is saved as a session. Numbered plan lines become task records, which power the local progress checkboxes and completion bar.

Where each AI concept is used

LangChain: the AI building blocks

ChatPromptTemplate defines the research and revision prompts. RecursiveCharacterTextSplitter breaks large source text into manageable chunks. ChatGroq calls the hosted Qwen model and returns the summary and timed plan.

LangGraph: the agent workflow

The graph keeps request state and decides the next step. A short question routes to clarify; a normal request routes through prepare_context and research_and_plan; feedback routes to revise.

LangSmith: observability and evaluation

When LANGSMITH_TRACING=true and a valid key are configured, LangSmith records every graph run, model call, prompt, latency, output, and error. The included evaluation dataset tests whether expected concepts appear in generated results.

Human-in-the-loop agent

The user is always in control. They can adjust the plan with a request such as “I have only 30 minutes a day.” The graph enters the revision path and produces a new, more realistic plan.

The AI agent in this project

Current architecture: one AI agent, not a multi-agent system. The agent is not just a single chat prompt: it uses state, chooses a workflow path, works with source context, and changes its plan after human feedback. The LangGraph nodes below are steps performed by the same agent, not independent agents.

1

It decides the next step

The LangGraph decide node inspects the current state. Very short or vague questions go to a clarification response; normal questions go to research; feedback on an existing plan goes to revision.

2

It uses tools and context

The agent works with loaded webpage text, uploaded PDFs, notes, a text splitter, prompt templates, and the hosted Qwen model. These tools help it create a grounded answer instead of answering from a blank chat window.

3

It keeps a useful state

State holds the question, prepared context, summary, task plan, and revision request. This lets the agent revise the same plan rather than starting again when the user says their available time has changed.

All agent components in the current code

One Research & Task Agent is compiled as research_agent. Its workflow steps are decide, clarify, prepare_context, research_and_plan, and revise. The ChatGroq Qwen model is the agent’s language model, not a second agent. The URL/PDF loader, SQLite storage, and LangSmith tracing are tools and observability components, not agents.

Source ingestion and grounding

Web pages

The app fetches public HTTP(S) links, removes navigation, scripts, and styling noise, then retains readable text. It rejects local URLs.

Uploaded files

PDF, TXT, and Markdown files are read in memory; they are not copied to a cloud storage bucket. AES-PDF support is included, and password-protected files return a friendly message.

Context preparation

Source text is split into overlapping chunks before reaching the model. This is a lightweight RAG-style foundation that keeps the prompt focused and is easy to understand.

Grounded output

The research prompt asks the model to rely on provided context for factual claims and to label no-source answers as general guidance.

Model and prompt behavior

Hosted free-tier model

The app calls Groq’s hosted qwen/qwen3.6-27b through the LangChain ChatGroq integration. No multi-gigabyte model is installed locally. A Groq API key is required, and the account’s free-tier limits apply.

Output settings

The model uses a low temperature of 0.2 for more consistent plans and a maximum of 700 output tokens. Reasoning is disabled and hidden, so users receive a direct answer rather than internal reasoning text.

Research prompt guardrail

When sources exist, the prompt says to use them for factual claims. Without sources, it instructs the model to label its answer as general guidance. This is a practical grounding guardrail, not a guarantee of factual accuracy.

Revision prompt

The revision node receives the current summary and task plan with the feedback. It creates a replacement plan; it does not silently mutate existing tasks or take actions outside the app.

Data, privacy, and safety

Local history

Research sessions and task completion live in the local research_tasks.db SQLite database. The file is excluded from Git.

Secret protection

API keys belong in .env. That file is ignored by Git and never included in the repository or this public site.

Explicit user actions

The agent recommends and revises; it does not send emails, make purchases, or alter external accounts.

Transparent errors

URL, file, PDF encryption, and cloud-model failures are presented separately so users see an actionable explanation rather than a vague failure.

How the project is tested

Evaluation tests: evaluate.py sends stable example questions through the agent and checks that a summary, task plan, and expected source concept are present.

Workflow tests: the app has been exercised through initial research, the LangGraph revision branch, persistent task completion, PDF handling, and Streamlit UI tests.

LangSmith test: with a valid LangSmith API key, send one request and inspect the ai-research-task-assistant project to view the nested graph and model trace.

Configuration, deployment, and limits

Required configuration

GROQ_API_KEY authenticates hosted model calls. The optional GROQ_MODEL selects the model. Keys are loaded from .env and the example file documents the variable names without including secrets.

Optional LangSmith configuration

Set LANGSMITH_TRACING=true, LANGSMITH_API_KEY, and a project name to observe the same LangChain and LangGraph calls in LangSmith. A key must be valid for the configured LangSmith region.

GitHub Pages guide

This documentation site is static HTML in docs/, published from the main branch’s /docs folder. It needs no JavaScript build process and links back to the public repository.

Current limitations

The context stage takes the first six chunks rather than semantic vector retrieval; generated tasks have no due dates; remote pages can change after they are loaded; and a cloud LLM can still make mistakes. These are intentional MVP tradeoffs to keep the code understandable.

Next development steps

True RAG retrieval

Add embeddings and a local vector store so the app retrieves the most relevant chunks rather than the first six source chunks.

Quality controls

Add source-level citations, a critic pass for unsupported claims, and more varied LangSmith evaluation examples.

Planning features

Add task due dates, priority, search across saved sessions, and optional calendar integration after explicit user approval.
